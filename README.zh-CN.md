# BILI: Basic Integrated Listening Infrastructure (Bilibili Music Player)

一个小巧的 PyQt6 桌面音乐播放器。通过 BV 号或公开空间列表收藏可访问的哔哩哔哩视频，将不同视频的歌曲整理成可编辑专辑，并在独立队列中播放音频。支持白天/夜晚主题和简体中文/英文界面，切换时不打断播放。

## 安装与启动

请先安装 Miniconda 或 Anaconda。在项目目录中，使用 Anaconda Prompt 或能够运行 `conda` 的终端执行下面的命令。脚本也支持 `CONDA_EXE`，并会根据自身位置定位项目根目录，因此使用脚本绝对路径时可以从任意工作目录启动。

Windows：

```bat
scripts\setup.bat
scripts\run.bat
```

Linux / macOS：

```bash
bash scripts/setup.sh
bash scripts/run.sh
```

安装脚本会查找名为 `bili` 的环境，不存在时新建，确保使用 Python 3.12，然后安装 [requirements.txt](requirements.txt) 中的依赖。启动与测试始终通过 `conda run --no-capture-output -n bili` 运行，不使用默认或 `base` Python 环境。

Windows 版 PyQt6 包含 Qt Multimedia 的 FFmpeg 后端，无需另行安装 `ffmpeg` 命令行程序。Linux 可能需要通过发行版安装系统显示、音频库，并提供可用的桌面会话及音频设备。

## 使用方法

以下正文描述当前版本；折叠的历史说明仅供参考，涉及独立歌曲副本、三种播放模式或旧版存档的旧规则不再适用。

### 歌曲与专辑文件夹

每首歌按 **BV 号＋分 P 序号** 唯一保存。专辑是按顺序引用这些共享歌曲的文件夹。导入一个 BV 的全部分 P 或导入空间列表时，每首歌也会自动登记到单曲库；重复导入相同 BV/P 会复用已有歌曲。

**全部** 分类显示所有专辑，以及没有放进任何专辑的单曲；**单曲** 分类仍显示完整歌曲库。移除单曲的最后一个专辑关联后，它会重新出现在全部分类中。此规则仅影响展示，不改变保存的歌曲或 JSON 导出范围。

- 从单曲卡片或任意专辑编辑歌曲名称、作者、日期或来源，都会更新音乐库中同一首歌，以及各专辑和歌曲信息页。
- 从专辑移除歌曲只解除该专辑的引用。删除专辑会保留歌曲及其在其他专辑中的引用；删除单曲本身则会删除歌曲，并移除所有专辑对它的引用。
- 播放队列中的每一项仍是独立的播放记录：同一首歌可以多次加入，每次都有独立队列 ID，同时关联共享歌曲。

### 新建与导入

- 点击 **＋ 新建专辑**，输入名称即可创建空专辑，无需 BV 号，之后再添加歌曲。
- 点击 **＋ 导入 BV**，输入 BV 号，例如 `BV1xx411c7mD`，或完整链接 `https://www.bilibili.com/video/BV1xx411c7mD/`。选择 **单曲 · 导入指定分 P** 导入某个分 P；选择 **专辑 · 导入全部分 P** 导入该视频的全部分 P。
- 导入时立即读取视频元数据和曲目，默认使用视频封面。名称留空时，专辑使用视频标题；歌曲名称按原视频的分 P 数量决定：原本只有一个 P 时使用视频主标题，多 P 视频使用各分 P 标题，即使只导入其中一个 P 也一样。向专辑添加 BV、导入列表同样遵循此规则。自定义名称按填写内容保留。
- 导入或编辑单曲时，可选填 **作者** 和 **日期**。两项都可留空，日期可填写任意文字，不要求固定格式。新导入时默认留空，不读取 UP 主或视频发布时间来填充。

### 导入空间合集或系列

1. 点击顶部的 **导入列表**，粘贴公开空间列表链接，例如 `https://space.bilibili.com/1459104794/lists/2029798`。
2. 点击 **读取列表**，预览原始标题、视频总数和封面。新版 `/MID/lists/ID` 链接会自动识别类型，也支持显式的 `?type=season` 或 `?type=series`，以及旧版空间合集、系列详情链接。
3. 按需修改 **专辑名称**。默认勾选 **导入全部分 P（取消勾选则仅导入每个视频的 P1）**，会把每个视频的全部分 P 导入为曲目；取消勾选后，仅导入每个视频的 P1。
4. 点击 **导入为专辑**。后台任务显示进度，期间可点击 **取消**。导入完成后才将新专辑加入音乐库；取消不会改变音乐库，也不会保存半成品专辑。

导入保留列表的服务端顺序，并对 BV 号去重，逐个读取视频真实的分 P 和 CID。专辑默认使用列表标题或你修改的名称，以及列表封面；列表没有封面时使用可用视频的封面。新歌曲的作者保持留空，已有歌曲的手填信息保留。每首歌登记到单曲库或复用已有歌曲，新专辑只保存对它们的有序引用。之后可编辑专辑名称、成员和顺序；B站列表之后的变化不会自动同步。

不可用或已删除的视频会跳过，并显示逐项报告。空列表或没有可播放曲目的列表会报错；连接故障和 API 限流会中止导入，不添加新专辑，已有音乐库数据保持不变。

示例链接实测为合集 **MyGO!!!!! 原创MV**，当时有 **25 个视频**；完整导入得到 **25 首曲目，跳过 0 个视频**。公开列表内容及可访问状态可能变化。

### 导出与导入整个音乐库 JSON

点击搜索框旁的 **JSON** 按钮，选择 **导出全部曲目 JSON…** 或 **导入 JSON 曲目…**。

- 导出包含音乐库中的全部专辑文件夹和唯一歌曲，保留音乐库顺序及各专辑内的歌曲顺序；专辑成员保存为共享歌曲 ID 的引用，空专辑也会导出。搜索词、筛选、所选卡片和播放队列都不会缩小导出范围。
- JSON 保留歌曲名称、来源 BV、分 P 和 CID、时长、手填作者、任意文字日期、封面与解析状态。文件只包含元数据，不含音频、播放队列、音量或播放器设置。
- 封面只保留不含用户名和密码的有效 HTTP(S) 网址，省略协议的 `//` 网址统一为 HTTPS。本地路径、封面缓存文件、`file:` 网址和内嵌图片数据会在导出封面字段中留空；导出不读取或复制这些文件，也不改变原音乐库及其封面。
- 请选择独立的目标文件。保存对话框会在覆盖已有导出文件前确认；播放器禁止覆盖当前正在使用的音乐库文件。导出通过原子替换写入所选文件。
- 导出使用 `format: "bili-music-library"`、`version: 2`，以共享歌曲及专辑引用保存关系。导入兼容旧版便携格式 1，以及播放器存档版本 1、2、3，仅提取音乐库数据。文件须为 UTF-8 JSON，可带 BOM，大小最多 16 MiB。不支持的格式、版本或非法图结构会在加入音乐库前整份拒绝。
- 导入按 BV/P 合并歌曲，已有歌曲及其保存的元数据优先；重复导入会复用这些实体，不创建重复单曲。导入的专辑文件夹保留曲目顺序，引用映射到合并后的歌曲。已有音乐库顺序保留，新条目追加到末尾。导入封面遵循相同的网址规则，不会打开文件中写入的本地路径。
- JSON 导入不请求 B站元数据 API。已解析歌曲直接保存；带有效 BV 号的未解析歌曲保持未解析状态，之后打开或播放时才解析。没有来源 BV 的专辑，包括空专辑，按本地文件夹处理并标记为已解析。

### 当前音乐库卡片与详情

白天和夜晚模式均采用粉色强调色。每张专辑或单曲卡片上方是方形封面，下方是标题与副标题。静止时卡片使用中性背景、无边框；悬停时显示面板高亮，唯一出现的悬停控件是封面右下角的粉色圆形 **播放** 按钮。

- 点击封面打开只读详情，不会自动播放。单曲显示独立信息页，包含大封面、标题、手填作者与日期、时长和来源；作者或日期为空时显示 **未填写**，不再重复显示单行曲目列表。
- 专辑详情保留曲目列表和滚动折叠头部：向下滚动时封面逐渐缩小，封面和元数据淡出，之后顶部固定栏只显示专辑名；向上滚动恢复完整头部。
- 专辑每首歌下方保留 **播放** 和 **插入队列**。**播放** 将独立队列项追加到队尾并播放这一首；**插入队列** 将新项插在当前曲目之后，不打断播放，没有当前曲目时追加到队尾。每次加入保留手填信息并获得新队列 ID，同时关联共享歌曲；保存歌曲编辑时，会同步关联队列项的信息。完整与迷你模式共用队列。
- 双击专辑歌曲打开共享歌曲的信息页，不会新增重复单曲。该页面与单曲卡片使用同一份曲名、作者、日期、来源和封面；点击 **编辑** 打开歌曲编辑器，而非专辑编辑器。保存歌曲后，所有引用它的专辑和信息页同步更新；删除专辑不会删除该歌曲。
- 详情底部的 **播放** 和 **添加到队列** 对当前显示的专辑或单曲生效，使用已保存的曲目顺序。

### 当前专辑与单曲编辑

在详情中点击 **编辑**，或右键卡片、封面、标题，选择 **编辑专辑** 或 **编辑**。专辑编辑器管理文件夹；歌曲编辑器管理全库共享的歌曲信息，专辑内歌曲的信息页也直接打开歌曲编辑器。

- 在专辑编辑器中修改专辑名称，在封面栏输入图片 URL，或通过 **选择图片** 使用本地图片。
- 使用 **添加 BV** 添加另一个视频的单个分 P 或全部分 P，并登记或复用单曲实体；使用 **添加已有单曲** 或单曲右键菜单的 **加入专辑…** 添加引用，不创建独立歌曲副本。
- 导入或编辑单曲时，可选填 **作者** 和 **日期**。在专辑编辑器中双击歌曲或点击 **编辑曲目**，也会打开这首共享歌曲的编辑器，可修改名称、作者、日期、来源 BV 与分 P。更改来源或分 P 会重新读取音频信息，并保留手填作者与日期；保存后同步到所有专辑及歌曲信息页。
- 在专辑编辑器中拖动曲目，或使用 **上移 / 下移** 调整该专辑内的顺序。在专辑只读详情中双击歌曲打开其信息页；需要播放时使用该行的 **播放** 按钮。
- **保存** 提交专辑名称、封面、成员和排序；**取消** 撤销尚未保存的专辑修改。单独保存的歌曲编辑已对全库生效，取消专辑窗口不会撤销这些歌曲编辑。

### 播放控制与外观

- 双击队列曲目播放，拖动调整顺序，右键移除。

- 提供播放/暂停、上一首/下一首、音量，以及 **顺序播放 / 列表循环 / 单曲循环 / 随机播放** 四种模式。完整和迷你模式都可点击进度条任意位置，直接跳到对应时间；也可拖动滑块，松开后定位。调整进度保持原有播放或暂停状态，暂停时不会因此自动播放。
- **随机播放** 按队列项随机选择，不改变可见队列顺序。每轮从尚未选中的队列项中抽取；有多个队列项时，不会连续选中同一项。相同歌曲多次加入队列仍作为不同项参与随机选择，因此相邻两项可能属于同一首歌。**上一首** 返回实际播放历史中的上一项；所选播放模式会保存到下次启动。
- 迷你模式播放按钮左侧的 **44×44** 模式按钮，与右侧同尺寸队列按钮对称。点击可打开四种模式的菜单，当前模式带勾选；与完整模式的模式下拉框保持同步。

- 点击 **关闭** 保留现有托盘行为：系统托盘可用时隐藏窗口，继续播放；可通过托盘菜单的 **退出** 退出播放器。系统托盘不可用时，关闭窗口会正常退出。

## 本地数据与旧版升级

音乐库、专辑成员与封面、队列顺序、音量、播放模式、主题和语言会保存在本地。首次启动为空音乐库，默认使用白天模式和简体中文；恢复队列后保持暂停，不自动继续播放。

当前存档版本为 **3**：单曲拥有按 BV/P 唯一的歌曲实体，专辑用 `song_ids` 保存有序引用，不重复保存歌曲元数据。手填名称、作者和日期属于共享歌曲；播放队列的每次加入仍保留独立 ID，并用 `song_id` 关联来源歌曲。旧队列迁移不会把播放记录 ID 改成歌曲 ID。播放模式保存为 `play_mode`，其中随机播放是第四种模式。

卡片大小也会通过外观设置 `card_scale` 保存，默认值为 `1.0`（100%）。Ctrl＋滚轮会修改已保存的比例，界面不显示数值。

数据文件为 Qt 用户应用数据目录 `QStandardPaths.AppDataLocation` 下的 `library.json`，组织名和应用名均为 `BiliMusic`，具体目录随操作系统变化。封面图片缓存在音乐库旁的 `covers` 目录中；保存本地专辑封面时，会将图片复制到该受管理缓存，之后删除原图也不会丢失已保存的封面。

兼容读取版本 **1、2、3** 音乐库。版本 1、2 在内存中迁移为共享歌曲模型，单独读取不会改写旧文件；之后首次保存写入版本 3，并在替换前创建与原文件字节完全一致的 `library.json.v1.bak` 或 `library.json.v2.bak`，已有备份不会覆盖。

旧存档中，同一 BV/P 若存在不同元数据，优先采用原音乐库中最早的独立单曲；没有独立单曲时，采用最早的专辑内副本作为共享歌曲。原始副本保留在首次保存前创建的备份中，迁移不会联网读取或重新命名歌曲；缺少作者或日期字段时按空白读取。旧版未解析专辑仍在首次打开或播放时解析，之后使用保存的歌曲引用及顺序。

保存使用原子替换；已有文件损坏时会保留原文件并报告错误，不会静默覆盖。

## 播放与访问限制

无需登录或提供 Cookie，仅支持公开可访问的视频。地区、付费或登录限制可能导致无法播放；API 请求可能被 B站限流，已删除或私密视频也无法解析。

客户端优先选择 DASH 音频，必要时回退到 API 返回的 `durl` 地址。本地流代理绑定 `127.0.0.1` 的随机端口，为媒体请求添加所需的 User-Agent 和 Referer 请求头，并转发 Range 请求以支持拖动进度。播放地址在请求播放时解析，不会存入音乐库。
