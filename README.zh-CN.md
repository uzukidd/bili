# BILI: Bilibili Integrated Listening Infrastructure (Bilibili Music Player)

一个小巧的 PyQt6 桌面音乐播放器。通过 BV 号收藏公开可访问的哔哩哔哩视频，将不同视频的歌曲整理成可编辑专辑，并在独立队列中播放音频。支持白天/夜晚主题和简体中文/英文界面，切换时不打断播放。

## 安装与启动

请先安装 Miniconda 或 Anaconda。在项目目录中，使用 Anaconda Prompt 或能够运行 `conda` 的终端执行下面的命令。脚本也支持 `CONDA_EXE`，并会根据自身位置定位项目根目录，因此使用脚本绝对路径时可以从任意工作目录启动。

Windows：

```bat
scripts\setup.bat
scripts\run.bat
```

Linux / macOS：

```bash
bash scripts/setup.sh
bash scripts/run.sh
```

安装脚本会查找名为 `bili` 的环境，不存在时新建，确保使用 Python 3.12，然后安装 [requirements.txt](requirements.txt) 中的依赖。启动与测试始终通过 `conda run --no-capture-output -n bili` 运行，不使用默认或 `base` Python 环境。

Windows 版 PyQt6 包含 Qt Multimedia 的 FFmpeg 后端，无需另行安装 `ffmpeg` 命令行程序。Linux 可能需要通过发行版安装系统显示、音频库，并提供可用的桌面会话及音频设备。

## 使用方法

### 新建与导入

- 点击 **＋ 新建专辑**，输入名称即可创建空专辑，无需 BV 号，之后再添加歌曲。
- 点击 **＋ 导入 BV**，输入 BV 号，例如 `BV1xx411c7mD`，或完整链接 `https://www.bilibili.com/video/BV1xx411c7mD/`。选择 **单曲 · 导入指定分 P** 导入某个分 P；选择 **专辑 · 导入全部分 P** 导入该视频的全部分 P。
- 导入时立即读取视频元数据和曲目，默认使用视频封面。名称留空时，专辑使用视频标题，单曲使用所选分 P 的标题；也可以输入自定义名称。
- 从 BV 导入的专辑最初包含一个视频的全部分 P，之后可以自由混入其他视频的歌曲。此操作不导入 B站合集或 `ugc_season` 系列。

### 编辑专辑

点击专辑封面，或打开卡片的 **··· → 编辑专辑**。所有修改先保留在编辑窗口内，点击 **保存** 后才写入音乐库；点击 **取消** 不会改变已保存的专辑。

- 修改专辑名称；在封面栏输入图片 URL，或点击 **选择图片** 使用本地图片。
- 点击 **添加 BV**，可添加另一个视频的单个分 P 或全部分 P。
- 点击 **添加已有单曲**，勾选要复制进专辑的单曲，原单曲仍保留在音乐库中。也可以使用单曲卡片的 **··· → 加入专辑…**，选择已有专辑。
- 拖动曲目，或使用 **上移 / 下移** 调整顺序。双击曲目或点击 **编辑曲目**，可修改名称、艺术家、来源 BV 号与分 P。更改来源 BV 或分 P 时，会重新读取对应音频信息后应用修改。
- 选中曲目后点击 **移除所选**。专辑可以保持为空；即使删光了从 BV 导入的全部歌曲，再次打开或播放也不会自动恢复原视频的分 P。

专辑会保存你选择的来源、曲名、艺术家和顺序。之后修改专辑，不会改变来源单曲，也不会改动已经复制进播放队列的歌曲。

### 播放与外观

- 卡片的 **播放** 会按照已编辑并保存的顺序将歌曲追加到队列末尾，并播放本次新加入的第一首；**＋ 队列** 只追加，不打断当前播放。空专辑不会加入任何歌曲。
- 双击队列曲目播放，拖动调整顺序，右键移除。音乐库卡片菜单也支持删除；有来源视频时，可在 B站打开。
- 提供播放/暂停、上一首/下一首、进度拖动、音量，以及 **顺序播放 / 列表循环 / 单曲循环** 三种模式。
- 右上角可切换 **白天模式 / 夜晚模式** 和 **简体中文 / English**，立即生效并保存到下次启动，不打断当前播放或清空队列。语言切换覆盖界面标签和对话框；用户输入的名称、原始视频元数据和服务器返回的消息保留原文。

## 本地数据与旧版升级

音乐库、专辑曲目与封面、队列顺序、音量、主题和语言会保存在本地。首次启动为空音乐库，默认使用白天模式和简体中文；恢复队列后保持暂停，不自动继续播放。

数据文件为 Qt 用户应用数据目录 `QStandardPaths.AppDataLocation` 下的 `library.json`，组织名和应用名均为 `BiliMusic`，具体目录随操作系统变化。封面图片缓存在音乐库旁的 `covers` 目录中；保存本地专辑封面时，会将图片复制到该受管理缓存，之后删除原图也不会丢失已保存的封面。

兼容读取版本 1 音乐库，单独读取不会改写旧文件。之后首次保存会写入版本 2，并在替换前创建字节完全一致的 `library.json.v1.bak` 备份；已有备份不会覆盖。旧版专辑在首次打开或播放时导入一次分 P，之后使用可编辑、已保存的曲目列表。保存使用原子替换；已有文件损坏时会保留原文件并报告错误，不会静默覆盖。

## 播放与访问限制

无需登录或提供 Cookie，仅支持公开可访问的视频。地区、付费或登录限制可能导致无法播放；API 请求可能被 B站限流，已删除或私密视频也无法解析。

客户端优先选择 DASH 音频，必要时回退到 API 返回的 `durl` 地址。本地流代理绑定 `127.0.0.1` 的随机端口，为媒体请求添加所需的 User-Agent 和 Referer 请求头，并转发 Range 请求以支持拖动进度。播放地址在请求播放时解析，不会存入音乐库。

## 测试

```bat
scripts\test.bat
```

```bash
bash scripts/test.sh
```

两端均在 `bili` 环境中运行 `python -m unittest discover -s tests -v`。API 解析与异常测试使用 mock，GUI 测试会在内部启用 Qt 离屏模式。这些测试不能证明某个实际 B站视频当前可播放。

如需额外检查实际视频的元数据、流地址和 Qt 媒体加载，可以传入一个公开可访问的 BV 号：

```bat
scripts\check_stream.bat BV1GJ411x7h7
```

```bash
bash scripts/check_stream.sh BV1GJ411x7h7
```

此检查使用临时音乐库，通过界面异步解析并短暂静音播放，确认进度开始推进后暂停，不会修改已保存的音乐库。检查需要联网，视频或 API 不可用时可能失败。追加 `--screenshot path.png` 可保存检查窗口截图，使用 `--help` 可查看参数。

追加 `--album` 可同时验证可编辑专辑导入、默认视频封面，以及播放中的外观切换。`--theme light|dark`、`--language zh_CN|en_US` 用于选择初始界面。`--preview-pair` 会把白天中文、夜晚英文和专辑编辑器截图保存到指定目录：

```bat
scripts\check_stream.bat BV1GJ411x7h7 --album --preview-pair .cache/appearance
```

```bash
bash scripts/check_stream.sh BV1GJ411x7h7 --album --preview-pair .cache/appearance
```
